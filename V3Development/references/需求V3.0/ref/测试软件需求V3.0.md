# 测试软件需求文档 V3.0

> 适用范围：数据采集 App（移动端），支持 **CUP 指尖 PPG 设备**与**腕部脉搏仪器**两类设备的蓝牙连接与数据采集（两类设备**不能同时测**）。腕部脉搏仪器在 PPG（RED/IR）基础上**新增心电（ECG）数据采集**，并更新数据传输协议（见第 5 章）。
> V3.0 在 V2.0 基础上形成**增量需求**：①腕部脉搏数据命名 `MB-{subject}-{seq}`（腕部仪器连接**保留当前方案**，暂无类型码）；②被试信息新增吸烟频率 / 饮酒频率选项、性别改为男 / 女单选；③SQI 显示增加颜色与提示区分；④**血压改为开始录制前填写（选填）、回看时可修改**；⑤**开始录制就绪条件与不可触发原因提示**；⑥**腕部仪器 ECG 心电数据采集与传输协议更新**；⑦**录制模式二选一（定时录制 / 录制）**，定时录制默认 1 分钟到时自动停止，停止键上显示倒计时或"手动停止"。
> 配套参考：`code/combo_sqi.py` 等（综合 SQI 算法子集，见 code/README.md）、`ref/综合SQI指标计算流程.md`（颜色 / 阈值 / 仲裁依据）。

## 1. 设备连接与设备类型

**1.1 双设备支持**

App 支持两类采集设备：**CUP 指尖 PPG 设备**（V2.0 已支持）与**腕部脉搏仪器**。当前版本已可选用腕部仪器进行连接和数据采集，腕部仪器的扫描、连接、订阅、数据接收与可录制判据**保留当前连接方案**，本章不再另行规定连接细节。腕部仪器**暂无类型码**，App 不要求自动识别设备类型。

V3.0 起，腕部脉搏检测仪在原有 PPG（RED/IR）基础上**新增心电（ECG）数据采集**，并启用更新的数据传输协议（第 5 章）；CUP 指尖设备不受影响（无 ECG）。

**1.2 双设备互斥（不能同时测）**

同一时间**只能连接并采集一台设备**：

- 指尖设备与腕部仪器**不能同时连接**、**不能同时录制**。
- 已连接一台设备时，如需改用另一台，须先断开当前设备，再重新扫描连接；更换设备后需重新确认命名 / 表单信息方可再次录制（与"当前未录制"前置条件一致）。

**1.3 与命名的关联**

由于腕部仪器暂无类型码、连接方案保持现状，建议名前缀（`PPG-` / `MB-`）**由用户在命名表单中选择**（指尖 PPG / 腕部脉搏 二选一，默认沿用上次选择），不依赖 App 对设备类型的自动判定，详见第 2.1 节。

## 2. 数据文件命名规范（新增 `MB-{subject}-{seq}`）

**2.1 建议名前缀在命名表单中选择**

文件名 stem 仍由用户自由命名（继承 V2.0 6.2/6.3 合法字符与强校验），默认建议名的**前缀由用户在命名表单中选择设备类型**（指尖 PPG / 腕部脉搏，默认沿用上次选择；因腕部仪器暂无类型码，不要求 App 自动判定，见 1.3）：

| 所选设备类型 | 建议名 | 示例 |
|---|---|---|
| CUP 指尖 PPG | `PPG-{subject}-{seq}` | `PPG-S001-1` |
| 腕部脉搏仪器 | `MB-{subject}-{seq}` | `MB-S001-1` |

- 小写前缀自动归一化为大写（`mb-S001-1` → `MB-S001-1`），与现有 PPG 行为一致。
- `subject` 合法字符、`seq` 从 1 起递增的规则不变。

**2.2 双命名空间的唯一性校验**

`PPG-*` 与 `MB-*` 是**两套独立的命名空间**，唯一性校验与序号建议均按前缀分别进行：

- **文件名维度**：stem 全局唯一（继承 V2.0 6.4，不分前缀——磁盘层不允许任何重名）。
- **(subject, seq) 逻辑维度**：按 `（设备前缀, subject, seq）` 三元组校验。`PPG-S001-1` 与 `MB-S001-1` **可以共存**，互不算重复——同一被试分别用指尖设备和腕部设备各采一次是正常场景，不是冲突。
- **自动建议下一序号**：选定 subject 后，seq 默认填 `当前所选前缀下该被试的 max(已有序号) + 1`。例：已有 `PPG-S001-1`、`PPG-S001-2`、`MB-S001-1`，选择腕部脉搏（`MB-`）时建议 `MB-S001-2`；选择指尖 PPG（`PPG-`）时建议 `PPG-S001-3`。
- **错误提示**沿用 V2.0 文案口径，但【次数重复】提示中带上前缀：`被试 S001 在 MB 前缀下的第 1 次采集已存在（文件 MB-S001-1），建议改用第 2 次`。重复校验同时纳入第 6.1 节录制就绪状态提示。

**2.3 数据格式与档案视图的适配**

- `{stem}.json` **不新增**设备类型字段（腕部仪器暂无类型码）：设备类型由 **stem 前缀**承载（`PPG-*` → 指尖、`MB-*` → 腕部）。主数据文件 `{stem}.csv` 结构不变（列定义继承 V2.0 8.2，采样率按设备协议配置）；腕部仪器的 ECG 数据**独立落盘** `{stem}_ecg.csv`（见第 5 章）。
- **被试档案库不拆分**：档案仍按 `subject` 组织（同一人的性别 / 年龄 / 吸烟 / 饮酒等稳定字段与设备无关）；档案视图内每次采集的条目天然带前缀可辨（如 `MB-S001-2`），可按 `PPG` / `MB` 分小节展示。
- **批量导出**在按 subject 分目录的基础上，目录内可再按 stem 前缀分子目录（`S001/PPG/…`、`S001/MB/…`），分组依据为文件名前缀；每个会话的全部产物（`{stem}.csv` + `{stem}_ecg.csv`（如存在）+ `{stem}.json`）一起导出。
- **训练侧对接**（接口约定，不属于 App 范围）：MB 文件名正则 `MB-([A-Z]+)-(\d+)`；聚合脚本（V2.0 附录 C.2）按 stem 前缀区分两类数据即可。

## 3. 被试信息采集增强

本章在 V2.0 第 7 章的两级字段模型上做增量：**性别改录入方式，吸烟 / 饮酒频率为新增的被试级字段，血压录入时机前移**。

**3.1 性别改为男 / 女单选**

- 录入控件由自由文本改为**单选**（单选按钮或下拉，二选一：`男` / `女`），必填、不允许空值与其他自定义值。
- 落盘不变：`gender` 存中文（`男`/`女`），`gender_code` 存编码（`男=1 / 女=0`），对齐 `subject_info.xlsx` 现有口径。
- 档案库回填时按存档值自动选中对应选项；历史数据中的非法值（如空）回填时清空待重选。

**3.2 新增：吸烟频率、饮酒频率（被试级，枚举单选）**

- **字段定义**（加入 V2.0 表 A 被试级字段表）：

| 字段 | 键 | 类型 | 必填 | 取值（枚举，四档） | 用途 |
|---|---|---|---|---|---|
| 吸烟频率 | `smoking_freq` | 枚举 | 选填 | `不吸烟` / `偶尔` / `经常` / `每天` | 生活习惯先验（分析 / 分层用） |
| 饮酒频率 | `drinking_freq` | 枚举 | 选填 | `不饮酒` / `偶尔` / `经常` / `每天` | 同上 |

- **交互**：与性别一致的单选 / 下拉控件；默认值为空（显示"请选择"），归档后回填最近值、可改。
- **必填性说明**：设为**选填**。理由：不拦截录制流程（对齐"资料不完整不阻断录制"的现行为），且旧档案 / 旧被试无此字段可兼容；正式采集流程建议在开始录制前补齐。若后续实验设计要求强制，仅需把校验从软提示升级为拦截，不影响数据结构。
- **落盘**：写入 `{stem}.json`（被试快照内），键名 `smoking_freq` / `drinking_freq`，存中文枚举原文；空 / 未选时存 `""`。同时入被试档案库（稳定字段），随 subject 修订版保存。
- **编码建议**（训练侧用，App 不落编码列）：`不吸烟/不饮酒=0、偶尔=1、经常=2、每天=3`，聚合进 `subject_info.csv` 时按需转换。

**3.3 `subject_info` 聚合列扩展**（接口约定）

批次聚合生成的 `subject_info.csv` 在现有 `subject,gender,age,height,weight` 基础上新增 `smoking_freq,drinking_freq` 两列（来自各 `{stem}.json`，按 subject 去重取最新）；`bp_record.csv` 不变。

**3.4 血压录入时机前移与回看修改（V3.0 修改）**

> 现行为：录制开始后通过"血压记录"弹窗录入参考血压。V3.0 改为**录前填写（选填）**，并在回看中开放修改。

- **录前填写（选填）**：`sbp` / `dbp` 移入**开始录制前**的被试信息表单（会话级字段，V2.0 7.3 表 B），与 subject / seq / 性别等一同填写。**不强制**：未填写不拦截开始录制（从第 6.1 节就绪条件中移除）。填写时保留 V2.0 的取值校验（收缩压 20–300、舒张压 10–250 mmHg、收缩压须高于舒张压）。
- **录制中不录入**：录制开始后**不再提供**血压录入弹窗 / 入口；界面只展示已填的参考血压值（未填则显示空）。
- **回看可修改**：录制结束后，在「已保存会话 → 详情 / 编辑被试信息」（V2.0 9.4）中可填写或修改本次会话的 `sbp` / `dbp`（录前未填的也可在此补填）：
  - 修改只作用于该会话的 `{stem}.json`（输出真值），可反复修改、保留最后值；不影响被试档案库，也不回写其他会话。
  - 若同时修改了 `subject` / `seq`，须重跑 V2.0 6.4 的 (subject,seq) 唯一性校验。
  - 建议（选做）：sidecar 记录 `bp_updated_at` 修改时间戳，便于区分原始录入与事后修正。

## 4. SQI 颜色与提示区分

> 参考实现：`code/combo_sqi.py`（V4.4.2 算法口径）；依据文档：`ref/综合SQI指标计算流程.md`。V3.0 将 SQI 从"纯数值"升级为"状态 + 颜色 + 提示文本 + 综合分"的单一「综合SQI」标签。
> ★V4.4.2 口径要点：**压力判定特征驱动**（不看分数）；SQI_tm 用**滤波后信号**口径（无 CPE）；flat 判定带**周期性豁免**；综合分仅作信息展示、不参与触发。

**4.1 显示形态**

界面上 SQI 区域显示**一个**综合标签，四要素：

```
[颜色] 提示文本 (综合分)
例：  绿色  信号良好 (0.93)
      橙色  信号不稳定 (0.81)
      红色  ⚠ 信号平直 (0.00)
      橙色  ⚠ 信号幅度过低 (0.00)
```

**4.2 输入指标与计算口径**

综合 SQI 的判定在**每 1 秒一帧的指标窗（最近 5 秒）**上计算，四类输入：

| 输入 | 算法 | 口径要点 |
|---|---|---|
| **SQI_tm** | 模板匹配（心拍窗口 → 逐拍与模板 Pearson 相关取均值） | 输入为**滤波后信号**（取负 → 滑动平均 2/2/10 → 带通 0.5–12 Hz），**无 CPE 峰值增强、无标准化**——CPE 是非线性变换、会虚抬弱/坏信号分数（实测过渡段旧口径恒 0.99、滤波后口径正确掉到 0.78–0.82） |
| **SQI_corr** | 自相关（40–150 bpm 内最大自相关值） | 对幅度 / 形态不敏感、只看周期性：真平直 ≈0.1、真周期波 ≥0.5。用于 flat 的周期性豁免（判"检出拍是真是假"）；**不能被 SQI_tm 替代**（平直噪声上 SQI_tm 可虚高至 0.49–0.73） |
| **flat** | 平直判别：`std/DC < 0.0003 或 p2p/DC < 0.0003` | 无有效信号（未贴好 / 接触不良 / 饱和） |
| **压力特征** | 特征点检测逐拍计算（P1 后 80ms 陡降度、P2 次波峰高度等） | 输出 4 闸门特征（n_beats / p2_height / init_steep / sev），见 4.4 |

**4.3 状态与颜色映射（优先级仲裁，命中即出）**

按优先级从高到低逐级判断，**短路返回**：

| 优先级 | 条件 | 状态 | 提示文本 | 颜色 | 综合分 |
|---|---|---|---|---|---|
| 1 | flat 命中 **且** 周期性豁免不成立 | `flat` | `⚠ 信号平直 (0.00)` | 红 | 0.0 |
| 2 | 压力 4 闸门全过（见 4.4，**特征驱动、不看分数**） | `pressure` | `⚠ 压力过大[(严重)] (分)` | 红 | SQI_tm×(1−0.85×sev) |
| 3 | SQI_tm ≥ 0.88 | `good` | `信号良好 (分)` | 绿 | SQI_tm |
| 4 | SQI_tm < 0.88 | `unstable` | `信号不稳定 (分)` | 橙 | SQI_tm |
| 兜底A | flat 命中但周期性豁免成立（低幅真周期波）且 SQI_tm 缺 | `unstable` | `⚠ 信号幅度过低` | 橙 | 0.0 |
| 兜底B | 指标全缺（采集中热身 / 预处理失败） | `unknown` | `综合SQI: --` | 灰 | 无 |

**flat 的周期性豁免**（治"重压低幅周期波被吞成平直"）：`豁免成立 ⟺ n_beats ≥ 2 且 SQI_corr ≥ 0.30`。豁免成立则不判 flat、继续往下仲裁（落到压力或 SQI_tm 分支）。双条件缺一不可——只看拍数不行：真平直的残余噪声经带通放大后特征检测也会"检出"假拍，SQI_corr 才是拍真假的判据（噪声在任何固定延迟不重复自己 → 贴 0）。SQI_corr 算不了时保守视为无周期证据、照判 flat。

**4.4 压力判定（特征驱动 4 闸门）与综合分**

**压力触发条件**（四道闸门全部满足，**不看综合分、不看 SQI_tm**）：

```
n_beats ≥ 2          （可检拍数下限，重压下可检拍本就少，2 拍即判）
且 p2_height ≤ 0.32   （★主判据：P2 次波峰被压塌程度，随压力单调降）
且 init_steep ≥ 4.0   （主峰陡降在，挡光滑无 P2 信号）
且 sev ≥ 0.40         （4 特征综合严重度，防单特征噪声）
```

- **为什么特征驱动**：按压时波形仍周期，模板匹配 SQI_tm 可能虚高（实测持续按压时 SQI_tm 回 0.99+）——分数驱动的旧方案会因分数回升而翻回"信号良好"。压力判定只认波形特征。
- **为什么 p2_height 是主判据**：P2（重搏波）随压力单调衰减（轻压 ~0.9 → 正常 ~0.7 → 重压 0.10–0.31），**P2 健在一律不报压力**。
- sev（压力严重度）= 4 个连续特征（init_steep / late_rebound / mid_min_vel / slow_frac）各自线性归一到 [0,1] 取均值；sev ≥ 0.80 时提示加 `(严重)` 后缀。
- **综合分**（信息量展示、**不参与触发**）：`score = SQI_tm × flat因子 × 压力因子`；压力因子 = `1 − 0.85 × sev`（sev < 0.40 时不惩罚 = 1）。

**4.5 阈值与常量**

| 常量 | 值 | 含义 |
|---|---|---|
| `sqi_tm_good` | **0.88** | 良好 / 不稳定分界（实测标定：良好信号恒 ≥0.91、不稳定段 0.75–0.86，0.88 卡两组之间无假阳性；注意这是滤波后信号口径，CPE 口径下不稳定段会虚高到 0.99、0.88 不适用） |
| `COMBO_P2_HEIGHT_MAX` | **0.32** | 压力主判据：p2_height 上限（正常 0.34–0.9、压力过大 0.10–0.31） |
| `COMBO_STEEP_MIN` | 4.0 | init_steep 下限（曾用 4.5，轻压段 4.2–4.9 横跨阈值逐帧抖 → 降 4.0） |
| `COMBO_OP_FLOOR` | 0.40 | 压力严重度最低门槛 |
| `COMBO_OP_SEVERE` | 0.80 | 加 `(严重)` 后缀的门槛 |
| `COMBO_MAX_PEN` | 0.85 | sev=1 时最大扣分（压力因子下限 0.15） |
| `COMBO_FLAT_EXEMPT_CORR` | 0.30 | flat 周期性豁免的自相关门（真平直 ≈0.1、真周期波 ≥0.5，0.30 居中） |
| `flat_rel_thr` | 0.0003 | 平直判别阈值（std/DC 或 p2p/DC） |
| `COMBO_DEBOUNCE` / `_EXIT` | 2 / 2 | 显示去抖：进入新状态 / 离开压力状态所需连续指标帧数 |

> 分界线提示：p2h 0.32 分界较窄（实测重压段帧 0.317 vs 中等力度段帧 0.332）；"中等力度不报、重压才报"的语义线为用户划定。新人群 / 设备若误报漏报，优先复查 `COMBO_P2_HEIGHT_MAX`。

**4.6 计算节律、去抖与数值刷新**

- **判定在后台指标帧上执行**（每 1 秒一帧，指标窗 = 最近 5 秒）；界面渲染只读结果，**去抖计数必须在指标帧上、不得在渲染层**——否则同一份 1s 快照被高频渲染连刷，"连续 N 帧"实际不存在，会造成状态交替闪烁（V4.4.2 的关键架构教训，制度化：判定逻辑只在后台跑）。
- **去抖**：进入任意新状态需连续 2 个指标帧（≈2 秒）同一新状态；离开压力状态同样 2 帧。数值（综合分）仍每帧实时刷新。
- 断开连接 / 数据停顿超时 / 重连：状态与去抖计数器一并重置为 `unknown`。

**4.7 空数据兜底与落盘**

- 无数据 / 未连接 / 热身期（首帧算出前）：显示灰 `综合SQI: --`；CSV 的 `sqi` 列口径不变（`sqi_valid=false`、值留空）。
- **建议**（选做）：`{stem}.csv` 在现有 `sqi` 三联子之外新增 `sqi_state` 列（state_key 前向填充），便于离线按状态分段统计；不新增则状态可离线由 sqi 值 + 平直标志重建。
- **录制与 UI 同口径**：录制落盘的综合 SQI 状态用同一套仲裁 + 去抖计算，回放与实时显示一致。
- MB 腕部设备的波形沿用同一套口径，采样率 / 滤波参数按设备协议配置；若腕部佩戴方式下"压力过大"判据不适用，可经配置关闭压力分支（届时综合 SQI 退化为 flat > SQI 二分，颜色规则不变）。
- **ECG 不参与综合 SQI**：综合 SQI 的计算口径仍基于 PPG（RED/IR）；ECG 通道（第 5 章）不进入状态机与综合分公式。

## 5. 腕部仪器心电（ECG）数据采集（V3.0 新增）

**5.1 概述**

腕部脉搏检测仪在原有 PPG（RED/IR）基础上**新增 ECG 心电采集通道**（ADS1292R），三类信号经同一条蓝牙链路、按统一帧格式传输。App 侧需求：协议解析、ECG 波形显示、ECG 独立落盘。

**5.2 数据传输协议（`ads1292r_packet_t`）**

帧结构（C 结构体，多字节字段一律**小端序**）：

| 字段 | 类型 | 字节数 | 说明 |
|---|---|---|---|
| `header[2]` | uint8 × 2 | 2 | 固定 `AB BA`，帧头定界 |
| `seq_no` | uint32 | 4 | 帧序号，小端序，从 0 自增（uint32 回绕） |
| `ecg[20]` | uint32 × 20 | 80 | ECG 采样值，20 样本/帧 |
| `red[4]` | uint32 × 4 | 16 | 红光采样值，4 样本/帧 |
| `ir[4]` | uint32 × 4 | 16 | 红外采样值，4 样本/帧 |
| `footer[2]` | uint8 × 2 | 2 | 固定 `CD DC`，帧尾定界 |

- **帧长固定 120 字节**，无长度字段——按帧头 / 帧尾定界 + 固定长度切帧。
- **发送节拍：每 40 ms 发送一帧**（帧率 25 帧/秒，数据量 ≈3 KB/s）。每帧携带 ECG 20 样本、RED/IR 各 4 样本，由此锁定采样率：**ECG 500 Hz（20 ÷ 0.04s）、RED/IR 各 100 Hz（4 ÷ 0.04s）**，ECG : PPG = 5 : 1。
- ECG 数值为 ADS1292R 原始 ADC 读数（uint32），App **不做符号转换 / 标定 / 取负**，原样落盘；显示层可做基础滤波（去基线漂移），不影响落盘。

**5.3 解析与校验**

- **定界校验**：`header != AB BA` 或 `footer != CD DC` → 该帧丢弃，在字节流中重新搜索帧头同步；校验失败计数入诊断信息。
- **连续性校验**：`seq_no` 应逐帧 +1（含 uint32 回绕处理）；跳变即判定丢帧，记录丢帧数 / 丢帧时刻入诊断信息（帧号、估算丢失样本数）。另可按发送节拍做**到达率监测**：正常应每 40 ms 收到 1 帧（25 帧/秒），持续低于该速率即为链路异常，在诊断信息中提示。
- **可录制判据不变**：数据流"可录制"仍基于 PPG（RED/IR）持续到达（现行判据）；ECG 缺失 / 丢帧**不阻断**录制，仅在诊断与回看中标注。

**5.4 波形显示**

- 实时界面**新增 ECG 波形通道**：与 RED / IR 并列展示（或通过通道切换按钮查看），时间轴与 PPG 对齐。
- ECG 波形采样率为 PPG 的 5 倍，显示时按视窗抽点 / 降采样绘制，不改变存储数据。
- ECG 信号质量评估（ECG-SQI）**暂不做**，后续可作为扩展。

**5.5 落盘**

- **新增独立 ECG 数据文件 `{stem}_ecg.csv`**（逐样本，500 Hz）：

| 列 | 类型 | 单位 | 说明 |
|---|---|---|---|
| `schema_version` | str | — | 固定 `ppgcollector_ecg_v1` |
| `session_id` | str | — | 与 `{stem}.csv` 同值 |
| `sample_index` | int | — | ECG 样本序号，从 0 自增 |
| `device_time_s` | float | s | `= sample_index / 500`（与主 CSV 的 PPG 时间轴同源对齐） |
| `frame_seq_no` | int | — | 该样本所属帧的 `seq_no`（丢帧溯源用） |
| `ecg` | int | ADC | ECG 原始读数（不转换、不取负） |

- **主 `{stem}.csv` 完全不变**（仍 100 Hz PPG 逐样本宽表 + 内联指标）；PPG 与 ECG 的时间对齐靠两文件共有的 `session_id` + `device_time_s`。
- `{stem}.json` 新增两键：`ecg_file`（指向 `{stem}_ecg.csv`，无 ECG 时为 `null`）、`ecg_sample_rate`（如 500，无 ECG 时为 `null`）。
- 会话导出 / 批量导出时，`{stem}.csv` + `{stem}_ecg.csv`（如存在）+ `{stem}.json` **三件套一起走**；删除会话同时删除 ECG 文件。

**5.6 CUP 指尖设备不受影响**

CUP 设备无 ECG 通道、沿用现行协议与文件格式（两件套：`{stem}.csv` + `{stem}.json`）；`ecg_file` / `ecg_sample_rate` 为 `null`。

## 6. 录制控制（就绪条件提示 + 时长设置）

**6.1 录制就绪条件与不可触发原因提示（V3.0 新增）**

> 现行为：开始录制按钮的可用条件不透明，用户不知道为什么点不了。V3.0 要求**按钮不可触发时必须说明原因**。

- **就绪条件清单**（全部满足才可触发「开始录制」）：

| # | 条件 | 未满足时的提示示例 |
|---|---|---|
| 1 | 会话名称合法且不重复（文件名 + (前缀,subject,seq) 双维度，见 2.2） | `文件名重复：MB-S001-1 已存在` / `次数重复：S001 在 MB 下第 1 次已存在` |
| 2 | 设备已连接 | `未连接设备，请先扫描连接` |
| 3 | **有数据读入**（合法数据流持续到达、新鲜） | `等待设备数据读入，波形出现后可开始录制` |
| 4 | 当前未在录制 | `正在录制中` |
| 5 | 被试信息必填项已填全（sbp/dbp 为选填，不拦截，见 3.4） | `请补齐被试信息必填项` |
| 6 | 存储空间充足（≥20 MB） | `存储空间不足，请清理后重试` |

- **状态提示行（常驻）**：「开始录制」按钮下方常驻一行**录制就绪状态**文字，动态列出**当前未满足**的条件（多条时逐项列出）；全部满足时显示"✓ 可以开始录制"并激活按钮。条件重新不满足（如数据断流）时按钮回到禁用并恢复对应提示。
- **特别要求**：界面需明确说明"**有数据读入后方可开始录制**"——未连接 / 无数据 / 数据断流时，就绪状态行必须给出对应原因，不允许按钮灰着无解释。
- 表单侧配合**失焦即校验**（V2.0 6.4）：名称框失焦即查重并红字标注【文件名重复】/【次数重复】+ 建议值，不必等点「开始录制」才发现。

**6.2 录制模式二选一：定时录制 / 录制**

录制前由用户选择录制模式（两个开始入口或一个模式开关 + 开始键）：

| 模式 | 入口 | 时长 | 结束方式 |
|---|---|---|---|
| **定时录制** | 「定时录制」按钮 | 需填写**录制时长**，默认 1 分钟（60 秒），可改 | **到时自动停止**（也可提前手动停止） |
| **录制**（手动） | 「录制」按钮 | 不填时长 | **手动停止**（不限时长） |

- **录制时长**（仅定时录制模式）：
  - 单位：秒或分钟任一（建议分钟 + 允许小数，或秒整数，实现取其一并固定）。
  - **默认值 1 分钟（60 秒）**——选定时录制时预填 60，多数采集直接采用。
  - 合法范围：**10 秒 ~ 60 分钟**；超出范围或非法输入时即时红字提示并回退为默认值。
- 模式与时长在录制开始时锁定，录制中不可切换 / 修改（与命名 / 被试信息运行锁定规则一致）。

**6.3 停止键上的倒计时 / 模式显示**

- **停止键即状态显示**：录制进行中，停止按钮上**直接显示**当前模式与剩余情况：
  - 定时录制：按钮显示**剩余时间倒计时**，如「停止 (剩 0:37)」；到时自动结束前倒计时持续刷新。
  - 手动录制：按钮显示**「手动停止」**字样，表明需用户主动停止。
- 到时自动结束的流程与手动点击停止**完全一致**：先排空已接受的录制队列，再完成文件与 metadata，最后弹出保存完成提示。定时录制到时前用户仍可**提前手动停止**（等效，不视为异常）。
- **计时口径**：倒计时按**已接受样本的数据时长**计（`已接受样本数 ÷ 采样率`），而非墙钟时间——避免设备短暂断流时"时间到了数据没够"，保证录制文件的实际数据长度不短于设定值。断流期间倒计时暂停，恢复后继续。

**6.4 边界与兜底**

- 自动停止过程中**禁止**再次开始录制，直至保存完成（防半写文件）。
- 时长未到但触发设备断连 / 退出界面等异常兜底（继承 V2.0 5.5）：立即停止并保存已采数据，`record_end` 照实记录，不等待补足时长。
- 录制中**不可修改**时长设定（与命名 / 被试信息运行锁定规则一致）；如需改，停止后重新设置再录。

**6.5 落盘**

`{stem}.json` 新增 `planned_duration_s` 字段（数值，单位秒；定时录制模式存设定值（默认 60）；手动「录制」模式存 `null`），并保留 `record_start` / `record_end` 可回算实际时长；`{stem}.csv` 不变。

## 7. 边界说明补充（V3.0）

**7.1 双设备同被试与互斥**
- 同一 subject 可分别存在 `PPG-{subject}-{seq}` 与 `MB-{subject}-{seq}` 两族会话，互不冲突；序号各自独立递增（见 2.2）。档案视图中同一次采集按前缀可辨设备类型。
- 双设备**不能同时测**（见 1.2）：两类数据只能先后采集，不存在同一时刻的双设备并行会话。

**7.2 枚举字段的旧数据兼容**
- 性别：旧记录 `gender` 原值保留；仅新建 / 编辑被试时强制单选。
- 吸烟 / 饮酒频率：旧 sidecar 无此键读取时按 `""`（未填）处理，聚合脚本兼容缺列。

**7.3 新增 JSON 字段向后兼容**
`smoking_freq` / `drinking_freq` / `planned_duration_s` / `ecg_file` / `ecg_sample_rate` 均为**新增键**，旧版本数据无这些键不构成错误；新版本 App 读取旧 sidecar 时按默认值（`""` / `null`）处理。

**7.4 SQI 颜色仅改显示层；ECG 不参与 SQI**
第 4 章的颜色 / 提示 / 去抖均为**界面显示逻辑**，不改变 `sqi` 的计算口径与落盘格式（V2.0 第 4 章、8.2 条款不变）；ECG 通道不进入综合 SQI 计算。

**7.5 录制模式不改数据格式**
第 6.2/6.3 节的定时 / 手动两种模式与自动停止不改 CSV 逐样本写入逻辑；样本数 = 实际录制秒数 × 采样率（定时模式自动停止时 ≈ 设定秒数 × 采样率）。

**7.6 ECG 相关边界**
- **ECG 丢失不阻断**：ECG 校验失败 / 丢帧只计数并标注，不影响录制启停（可录制判据基于 PPG，见 5.3）。
- **文件可缺**：CUP 会话与 ECG 全丢的 MB 会话无 `{stem}_ecg.csv`，读取端以文件存在性 + `ecg_file` 是否为 `null` 判断，缺文件不构成错误。
- **时间轴对齐**：ECG 500 Hz 与 PPG 100 Hz 靠 `session_id` + `device_time_s` 同源对齐；两文件 `sample_index` 各自独立、不做行级一一对应。
- **丢帧溯源**：`{stem}_ecg.csv` 的 `frame_seq_no` 列保留帧号，离线可精确重建丢帧位置与时长。
